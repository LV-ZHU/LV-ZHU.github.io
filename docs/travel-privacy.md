# Travel 数据隔离上线说明

详细地点保存在 `users/{uid}/travelPrivate/maps`；排行榜只读取 `travelLeaderboard/{uid}`，字段为名称、头像、三个地图的去过数量、总数和更新时间。名称不再回退到邮箱，排行榜不再逐个读取 users 文档。

`firestore.travel.rules` 是待合并的规则片段，尚未部署或通过模拟器验证。上线前必须读取并备份现有规则，将这三个路径的规则合并进去，保留评论等其他功能的规则。务必移除任何同时覆盖这些路径的宽泛授权；Firestore 的多个 allow 条件按 OR 生效，新增拒绝条款不能撤销旧授权。

先收紧旧 travelData 的访问、开放新路径，再发布前端。旧客户端届时无法继续写入，需刷新。旧数据不批量删除：本人登录后读取自己的旧文档，写入新结构。退出排行榜只删除公开摘要，同时保存退出状态；私人地图保留。

部署前用 Firestore Emulator 验证：匿名和其他账号不能读取私人地图或旧文档；旧集合不能列表查询；公开列表最多 50 条；用户不能写删他人的摘要；摘要中增加 china/world/shanghai/email 等字段应失败；本人能保存地图和摘要并退出排名。当前计数仍是用户自报，不具备防刷榜保证。

本地构建和摘要单元测试不代表线上规则已生效。历史公开摘要如含额外字段，需要管理员先审查并清理后再开放读取。
